One particularly important improvement: make sure your Saga handles failures at every stage, including a service crashing after a database commit but before publishing its Kafka event.

## D. Security and authentication

You already planned JWT and Spring Security. Take that further:

- Access token and refresh token rotation.
- Refresh token revocation and logout.
- Role-based access control: `CUSTOMER`, `ADMIN`, `FRAUD_ANALYST`.
- Method-level security using `@PreAuthorize`.
- BCrypt password hashing.
- OTP attempt limits, resend cooldown and expiry.
- Secure CORS configuration.
- API rate limiting per user.
- Secrets managed through environment variables or a secrets manager.
- Audit login attempts and sensitive operations.

Also distinguish payload hashing from authentication: use HMAC when you need to verify that a payload was produced by someone holding a shared secret. Plain SHA-256 alone does not prove who sent it.

# 5. What I would consider optional

These can make the project more impressive, but I would not prioritize them over correctness and reliability.

- Kubernetes and Helm.
- Elasticsearch/OpenSearch for transaction search.
- WebSocket notifications for real-time fraud alerts.
- Scheduled reconciliation jobs.
- Multi-currency support and exchange rates.
- Feature flags for enabling/disabling fraud rules.

Avoid adding microservices just to increase the service count. A well-designed system with 7–9 meaningful services is better than 15 services with unclear responsibilities.

## 7. One important recommendation before we start

I would treat this as one long-running engineering project, not as a collection of tutorials.

For every feature, we should follow this cycle:

1. Understand the business requirement.
2. Design the architecture and data model.
3. Identify success and failure scenarios.
4. Implement the backend.
5. Write unit and integration tests.
6. Test through Postman or the React frontend.
7. Document the design decisions and trade-offs.

My recommendation: start with Phase 1 – Double-entry Ledger + Idempotency + Concurrent Transfer Handling. These three features will strengthen the foundation of your existing banking system more than adding another technology right now.
