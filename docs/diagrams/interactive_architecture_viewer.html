  • MySQL: b_transaction_service_db
Account Service Port 8081
  • Account lifecycle & 12-digit number generator
  • SAGA Step 1: PUT /{acc}/deduct
  • SAGA Step 4/Compensate: PUT /{acc}/credit
  • Freezes accounts on fraud.detected
  • MySQL: a_account_service_db
Fraud Detection Service Port 8084
  • Sub-millisecond stream analytics
  • Rule 1: Velocity (>5 tx in 60s sliding window)
  • Rule 2: Moving Avg Spike (>5x baseline)
  • Rule 3: Balance Drain (>90% of total balance)
  • Emits fraud.check.clean or verification.required
Notification Service Port 8085
  • Omnichannel asynchronous event hub
  • Sends OTP challenge messages via SMS/Email
  • Debit & Credit receipts on completed transfers
  • Security alerts on fraud and refunds
  • Stateless & decoupled consumer
Payment Service Port 8083
  • External Razorpay Payment Gateway SDK

  • Webhook callback processor (payment.captured)

Step-by-Step Execution Lifecycle

1 Client Transfer Request: User calls POST /api/v1/transactions/transfer. API Gateway checks Redis token bucket.
2 Synchronous Fund Reservation (SAGA Step 1): Transaction Service calls Account Service via OpenFeign PUT /deduct. Balance is reserved immediately.
3 Kafka Event Streaming (SAGA Step 2): Transaction is saved in DB with status PROCESSING. Event transaction.initiated is published to Kafka.
4 Fraud Evaluation: Fraud Detection Service consumes event and checks Velocity (Redis), Moving Average (Redis), and Balance Drain (Feign).
5A Clean Path: Emits fraud.check.clean ➔ Status updated to COMPLETED ➔ transaction.completed event credits receiver and notifies parties.
5B Suspicious Path: Emits verification.required ➔ 6-digit OTP saved in Redis with 5-minute TTL ➔ User challenged via SMS.

1. Velocity Counter (Sliding Window)

Key: fraud:velocity:{accountNumber}

Long count = redisTemplate.opsForValue().increment(key);
if (count == 1) {
    redisTemplate.expire(key, 60, TimeUnit.SECONDS);
}
if (count > maxTransactionsPerMinute) {
    return true; // Velocity limit exceeded!
}

Flags rapid bot transfers (> 5 transactions within 60 seconds).

2. Spending Spike (Moving Average)

Key: fraud.avg_amount:{accountNumber}

BigDecimal threshold = avgAmount.multiply(
    BigDecimal.valueOf(suspiciousAmountMultiplier)
);
BigDecimal newAvg = avgAmount.add(amount)
    .divide(BigDecimal.valueOf(2), 2, RoundingMode.HALF_UP);
redisTemplate.opsForValue().set(avgKey, newAvg.toString());
return amount.compareTo(threshold) > 0;

Flags sudden abnormal spending spikes exceeding 5X baseline average.

3. OTP Storage & Invalidation

Key: verification:otp{transactionId}

// SET with 5-minute automated eviction
redisTemplate.opsForValue().set(otpKey, otp, 5, TimeUnit.MINUTES);

// Atomic Invalidation upon verification
String storedOtp = redisTemplate.opsForValue().get(otpKey);
redisTemplate.delete(otpKey); // Anti-replay deletion

Guarantees single-use OTP challenge and prevents replay attacks.

Distributed Consistency: Hybrid SAGA Architecture

In a Database-per-Service architecture, two-phase commit (2PC) creates blocking locks and single points of failure. This system maintains Eventual Consistency using local ACID transactions and compensating actions.

▶️ Forward Actions (Happy Path)

  1. Sender account debited synchronously via OpenFeign.
  2. Transaction recorded with status PROCESSING.
  3. Kafka transaction.initiated event dispatched.
  4. Clean verdict received from Fraud Detection Service.
  5. Transaction marked COMPLETED.
  6. Receiver credited via transaction.completed Kafka event.

⏪ Compensating Actions (Rollback Path)

  1. Wrong OTP or Expired OTP detected on /verify.
  2. Compensating REST call: AccountService.creditBalance() refunds sender.
  3. Transaction status set to FLAGGED with audit failure reason.
  4. Event fraud.detected emitted ➔ Account Service blocks compromised account.
  5. Event transaction.refunded emitted ➔ User alerted of refund.
